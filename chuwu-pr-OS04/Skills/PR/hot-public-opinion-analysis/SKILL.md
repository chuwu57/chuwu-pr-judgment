# 热点舆情分析

> 分享版说明：先读[依赖与使用范围](../../../docs/DEPENDENCIES.md)。本包保留方法与工具，未包含个人知识库、历史案例及运行状态；未附带的知识路径不代表已读取的证据。


> 归属说明：本Skill由初五维护，属于初五的个人Skill体系。分享或再分发时请保留本归属说明及已有来源、作者和许可声明。

## 定位

舆情分析不是热度复述，而是把外部事件转成业务判断。

每次都要回答四个问题：

- 它有没有从单点信息变成群体性意见。
- 它真正冒犯了谁，为什么能被放大。
- 它接下来会升级、降温、反转，还是进入长期议题。
- 它和我们的品牌信任、业务风险、公关资产有什么关系。

默认输出要能直接转发给业务方。不要写学术论文，不堆材料。

## 知识调用

默认按本文件完成舆情研判。遇到爆料格式、跨平台扩散、群体身份投射、责任归因、回应必要性或业务动作取舍时，读取 `references/knowledge-map.md`。

知识调用顺序是：事实核验优先，案例和框架校准其次，理论只用于帮助判断背后机制。不要把理论名写成正文主轴。

## 先做事实核验

先查清楚再判断：

- 决策主体：是在替涉事组织、同行品牌、渠道／平台还是旁观组织判断。主体不同，业务相关性和回应责任不同。
- 时间锚点：结论对应哪个日期、时段或事件阶段。历史Evidence只能支持当时切片，不能自动证明当前仍在发酵。
- 源头：当事人、媒体、监管、平台、网帖、截图还是二手转述。
- 扩散：是否跨平台，是否有媒体、KOL、热榜、官方或监管介入。
- 信源等级：官方公告、权威媒体、行业媒体、自媒体、匿名帖、无法溯源截图。
- 关键数字和时间线是否有原始出处。

规则：

- 网帖、媒体与官方声明均按具体主张核验；来源身份不自动证明内容真实。未经核验的说法只作为舆论场内容，第一手材料可支持其实际证明的事实。
- 官方口径与当事人材料冲突时，比较原始证据、时间和独立验证；未解决则保留冲突，不以身份直接覆盖证据。
- 无法确认就写「待核实」，不要补故事。
- 用户没有说明决策主体或时间锚点时，先写明合理假设；如果不同假设会改变结论，则只给条件判断，不替用户暗定主体。

## 判断顺序

### 1. 是否已经形成舆情

舆情是针对特定话题的群体性意见，不是单条内容。

证据充分时分三档：

- **已形成舆情**：跨平台扩散，媒体/KOL 跟进，出现固定标签，进入公共议题或热榜。
- **舆情前夜**：还没爆，但具备被放大、借势、翻旧账、类比本业务的条件。
- **尚未形成舆情**：仍是局部讨论、单点投诉、未经验证传闻。

传播范围、平台节点或群体意见证据不足时，输出**传播证据不足，暂不可分档**。这不是「尚未形成舆情」；危机伤害和业务行动也不必等待舆情分档后才处理。

### 2. 舆情实质

不要只写谁受损、谁受益。先问：

- 这件事冒犯了谁。
- 哪种群体情绪被激活。
- 它被包装成了什么公共标签。
- 为什么是现在发酵。
- 有没有行业旧矛盾、社会情绪或价值观冲突在借题发挥。

输出要穿透表象，但语言要白。可以借理论帮助思考，不要把理论写成正文。

### 3. 走势研判

判断所处阶段：

- 潜伏期：零星信息，矛盾还没被广泛看见。
- 激化期：同类案例串联，标签出现。
- 爆发期：热榜、主流媒体、监管、头部 KOL 介入。
- 反转期：新证据、新主体、新时间线改变判断。
- 降温期：信息增量减少，讨论分散。

没有连续传播证据时输出「阶段暂不可判断」，不要把单一历史Evidence自动写成潜伏期、爆发期或降温期。

看几个升级条件：

- 是否还有关键事实没披露。
- 是否容易被一句话标签化。
- 是否有更多同类案例可串联。
- 是否贴近政策、监管、社会情绪或行业旧账。
- 当事方回应是否可能激化矛盾。

不要做绝对预测。用条件句写清楚：如果出现什么，会怎样；如果没有新增事实，会怎样。

### 4. 对业务的参考意义

最后必须回到业务：

- 我们是否会被类比、误伤、翻旧账或截图对比。
- 是否涉及安全、价格、履约、劳动者、未成年人、老年人、宠物健康、数据隐私、消费公平、社会责任等风险因子。
- 是否影响品牌信任、行业语境、媒体关系、话语体系、内部风险治理。
- 是否需要自查事实、规则、投诉、历史口径、渠道动作或已有预案。

不是所有热点都值得投入资源。没有业务相关性，就明确写「观察即可」。

## 输出结构

```text
判断基准
写明决策主体、时间锚点和关键证据缺口。

一、是否已经形成舆情
给明确分档和一句理由；证据不足时明确写「暂不可分档」。

二、舆情实质分析
写这件事为什么会被放大，背后的情绪和公共标签是什么。

三、舆情走势研判
写当前阶段、升级条件、降温条件。

四、对业务的参考意义
写和我们有什么关系、需要查什么、是否进入下一步动作。
```

## 转入最终决策

本Skill只完成舆情状态、实质、条件走势、责任边界和风险暴露。用户还需要决定是否回应、由谁回应、动作优先级或承担何种代价时，再按`Domains/PR/45-Workflows/Workflow_PR-Skill-Handoff.md`输出八字段交接包，交给`judgment-hub`收口。决策主体和时间锚点必须独立填写；证据、反证与缺口不得混写。

交接包中的「资产与业务影响」只写已经识别的暴露，「可选动作及代价」只保留会改变选择的方案。不要在上游先完成一遍最终取舍，再让下游重复判断。

## 质量红线

- 不编造来源、数据、链接、时间线、动机和公众反应。
- 不把热度当影响。
- 不把外部事件硬拉到本业务。
- 不把「传播证据不足」改写成「尚未形成」，不把历史传播阶段改写成当前状态。
- 不写「加强沟通」「高度关注」这种空话。
- 不替法务、监管、业务直接定责。
- 不把学术概念当输出。
- 不用长表格稀释判断。

如果分析后问题变成「我们要不要回应、自查、做预案、调整动作」，用八字段交接包转入 `judgment-hub` 做最终取舍。
