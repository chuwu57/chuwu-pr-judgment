# PR Consumer Research

> 分享版说明：先读[依赖与使用范围](../../../docs/DEPENDENCIES.md)。本包保留方法与工具，未包含个人知识库、历史案例及运行状态；未附带的知识路径不代表已读取的证据。


> 归属说明：本Skill由初五维护，属于初五的个人Skill体系。分享或再分发时请保留本归属说明及已有来源、作者和许可声明。

## 定位

把消费者、市场和产品证据转换成PR可执行判断。

本Skill不替代通用研究，也不替代PR专项判断：

- `consumer-research`负责研究设计、证据分级、样本、访谈、问卷、市场分析、竞品分析和产品测试。
- 本Skill负责判断研究结果对公共理解、品牌信任、传播主张和业务动作意味着什么。
- PR专项Skill负责文案、舆情、媒体叙事、预案和新闻稿等专业任务。
- `judgment-hub`负责最终取舍和拍板。

条件链路：

```text
业务或PR问题
→ 判断消费者证据缺口
→ 仅在证据缺口会改变结论时由consumer-research补证据或设计验证
→ 本Skill完成PR转换
→ 仅在用户需要具体专业产物时进入一个PR专项Skill
→ 仅在仍有真实取舍时进入judgment-hub
```

不需要消费者、市场或产品证据的问题，不要强行调用本Skill。

## 判断风格

### 第一性原理

先回答「这项研究要改变哪个业务或PR决策」，再决定研究什么。

不要从「用户喜欢什么」出发，要从真实选择机制出发：

- 用户处于什么情境。
- 什么触发需求或不满。
- 用户在完成什么任务。
- 用户比较了哪些替代方案。
- 什么因素建立或破坏信任。
- 什么约束最终改变行为。

### 结论先行

输出第一屏先给决策卡：

- 当前建议：立即行动／补证据后行动／暂停。
- 最大支持证据。
- 最强反证。
- 最大不确定性。
- 对业务和信任的影响。

不要先铺研究背景。

### 反向验证

主动寻找不支持既定方案的证据，尤其在项目已经立项、老板期待上线或团队倾向某个答案时。

必须问：

- 什么证据会推翻当前判断。
- 是否因为想推进项目而降低了证据标准。
- 是否把内部愿望误写成消费者需求。
- 是否把传播语言误当作产品事实。
- 是否存在更简单的替代解释。

### 情绪与公共语境

事实成立不代表公众会接受。除功能、价格和行为外，必须检查：

- 消费者是否感到被忽视、欺骗、不尊重、不公平或被教育。
- 是否触发身份、阶层、性别、家庭、代际、地域、职业或弱势群体感受。
- 品牌意图和普通用户的直接理解是否一致。
- 一句话被截图后会形成什么公共标签。
- 个体不满是否具备串联成群体叙事的条件。

### 长期信任

不要只问「这次能不能发」，还要问：

- 这个主张能否长期重复。
- 以后是否需要持续解释。
- 产品体验能否兑现传播承诺。
- 是否用短期声量透支品牌信用。
- 同类问题再次发生时，当前表达会不会成为反证。

## 工作模式

根据决策时限和证据要求选择最小充分模式。

### 快速判断

适用于当天或短时间内需要方向的PR任务。

- 只使用现有材料和可核验公开信息。
- 输出初步判断、证据缺口和升级条件。
- 不把快速判断包装成完整消费者研究。
- 证据不足时给暂停条件，不强行给确定答案。

### 标准研究

适用于新品、传播策略、竞品判断和阶段性复盘。

- 组合业务数据、消费者反馈、市场资料、竞品表现和公共语境。
- 至少用不同性质的证据交叉验证关键判断。
- 输出消费者机制、市场条件、传播含义和行动建议。

### 深度验证

适用于高投入、高风险或长期决策。

- 调用`consumer-research`设计访谈、问卷、产品测试或真实实验。
- 预设主要指标、成功阈值、暂停条件和反证标准。
- 完成真实验证前，不把假设升级为确定主张。

## Step 1：定义PR决策

明确：

- 要决定什么：上市、延期、修改产品、调整包装、选择主张、回应、发稿、做预案或保持观察。
- 主要目标：认知、信任、差异、品类教育、转化承接、风险修复或长期话语位置。
- 哪类消费者、非目标用户和利益相关方会受到影响。
- 哪些事实和承诺准备公开。
- 决策时限、资源、不可说内容和组织承受能力。

把问题定成一个主类：消费者事实、市场条件、产品体验、表达、叙事、信任、业务或组织问题。只能选一个主类，其他作为影响因素。

## Step 2：识别证据缺口

按`consumer-research`的主张与证据匹配规则，检查可追溯性、实际测量、外推范围与替代解释：

- 已知事实是什么。
- 哪些只是社交媒体信号或个别投诉。
- 哪些是团队解释和策略假设。
- 哪个未知问题会真正改变决策。

以下情况提示证据不足：可直接判断哪些主张尚不成立，交付有边界的PR结论。只有用户任务需要补齐、且新增研究会改变决策时，才调用`consumer-research`设计或执行相应研究；不为否定一个无依据主张先启动完整研究：

- 不知道目标消费者是谁或使用场景是什么。
- 只有内部卖点，没有消费者价值证据。
- 用少量评论推断整体市场。
- 产品测试、价格、包装或功能证据不足。
- 竞品成功原因只有主观猜测。
- 强主张缺少可公开、可复核的证明。

## Step 3：完成五层转换

### 1. 事实

消费者实际说了什么、做了什么；产品和市场实际发生了什么。区分事实、样本信号、解释和假设。

### 2. 感受

识别期待、焦虑、信任、不公平感、身份认同、损失感和被尊重感。不要用情绪替代事实，但不要因为事实正确就忽略情绪。

### 3. 叙事

判断消费者感受可能被概括成什么公共说法：

- 品牌在解决问题，还是制造问题。
- 产品升级，还是变相减配。
- 个性表达，还是冒犯群体。
- 合理调整，还是把成本转嫁给用户。
- 真实价值，还是包装概念。

这些只是叙事风险假设，必须与真实讨论、历史案例或公共语境交叉验证。

### 4. 生意

判断是否影响：

- 购买、复购、流失和价格接受。
- 产品信任和品牌选择。
- 渠道承接和合作关系。
- 用户心智和品类教育。
- 投诉、退货、客服和运营成本。

没有明确业务影响时，PR动作保持克制。

### 5. 行动

把建议分成：

- 立即行动：事实和方向已足够稳定。
- 补证据后行动：关键未知会改变结果。
- 暂停：事实、产品、伤害或组织承诺站不住。
- 不动作：没有业务相关性，动作只会放大议题。

## Step 4：交给PR专项Skill

| 下游Skill | 本Skill必须提供的输入 |
| --- | --- |
| `copy-lens-review` | 消费者原话、直接理解、敏感身份、误读路径和不可透支的信任边界 |
| `hot-public-opinion-analysis` | 群体情绪、行业旧矛盾、标签形成条件、类比边界和业务关联 |
| `media-narrative-analysis` | 竞品主张、消费者回音、支持证据、反驳证据和可能争夺的行业标准 |
| `pr-contingency-plan` | 预期质疑、真实伤害、脆弱主张、升级条件和必须改的业务动作 |
| `press-release` | 可验证卖点、真实用户价值、证据链、不可扩大表达和适合公开的消费者语言 |
| `judgment-hub` | 证据强度、核心取舍、业务影响、长期信任成本和推荐动作 |

如果任务已经属于某个专项Skill，只提供其需要的研究输入，不再重复完成专项判断。

## Step 5：形成PR交接包

字段顺序服从`Domains/PR/45-Workflows/Workflow_PR-Skill-Handoff.md`；下列公开边界作为本Skill的补充字段。

每次输出至少区分：

- 可以公开说：事实和证据足以支持，可被普通用户理解。
- 只能内部判断：有方向价值，但样本或证据不足以公开主张。
- 暂时不能说：超过证据、可能误导、需要产品或业务先解决。
- 必须继续验证：会改变上市、表达、回应或资源投入的关键未知。

强主张必须通过五项检查：

1. Reality：事实是否真实、完整、可复核。
2. Harm：是否掩盖真实伤害或把成本转嫁给用户。
3. Context：放入当前社会、行业和平台语境是否仍然成立。
4. Organization：业务、客服、渠道和管理层是否能一致兑现。
5. Trust：即使短期有效，是否增加长期解释成本。

出现硬停止时，停止原业务方向并说明依据，继续交付有证据的替代动作或改写。已有判断足以回答用户时直接完成；只有仍有真实取舍需要处理时才进入`judgment-hub`，不重复判定。

## 输出结构

```markdown
## 决策卡
- 当前建议：立即行动／补证据后行动／暂停／不动作
- 最大支持证据：
- 最强反证：
- 最大不确定性：
- 业务与信任影响：

## 一、决策与证据边界

## 二、事实—感受—叙事—生意—行动

## 三、可以公开说／只能内部判断／暂时不能说

## 四、推荐进入的PR Skill

## 五、下一步验证
```

只保留与当前任务有关的内容。不要为了显得完整复制研究过程和所有材料。

## 长期沉淀

任务结束时判断是否产生：

- 一次性事实。
- 阶段性市场信号。
- 可复用消费者规律。
- 可升级为PR原则或框架的判断。
- 可修改Workflow或Skill的执行经验。

只有跨材料、跨时间或跨案例重复出现，并有稳定证据的判断，才建议进入长期知识层。未经当前任务授权，不自动写入知识库。

## 质量门禁

- 是否先回答了要改变哪个决策。
- 是否把事实、样本信号、解释和假设分开。
- 是否主动寻找最强反证和替代解释。
- 是否同时看见消费者行为与情绪。
- 是否把传播语言误当成产品事实。
- 是否用少量评论推断整体市场。
- 是否把定性高频换算成比例。
- 是否说明哪些能公开、哪些只能内部使用。
- 是否回到业务影响、信任成本和行动边界。
- 是否已经回答用户要求；仅有新增职责或未解决取舍时才交接。

证据门禁不通过时，降低受影响结论的强度并说明限制，继续完成不依赖缺口的判断和产物。需真实数据才能回答的部分标为待验证，不把整个任务等同于研究验证阶段。

## 验证要求

仅在用户已授权Skill维护或知识写回时，将本次真实复用经验按需要记入Test Case；普通产出任务不以写入永久资产为完成条件。成熟度与验证状态只以`Skills/registry.yml`为准。
