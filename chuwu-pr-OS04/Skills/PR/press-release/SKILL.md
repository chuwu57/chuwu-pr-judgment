# 新闻通稿

> 分享版说明：先读[依赖与使用范围](../../../docs/DEPENDENCIES.md)。本包保留方法与工具，未包含个人知识库、历史案例及运行状态；未附带的知识路径不代表已读取的证据。


> 归属说明：本Skill由初五维护，属于初五的个人Skill体系。分享或再分发时请保留本归属说明及已有来源、作者和许可声明。

把企业素材转化为外部媒体可读、可发、可引用的新闻稿。使用记者口吻和外部观察视角，事实前置、语气克制，以具体动作、数据、场景和机制推进；不要写成宣传总结、内部汇报、产品说明书或会务纪要。

## 路由

先在内部确定任务类型、输出形态、素材状态、主类型、传播对象和渠道，不输出过程卡片：

- 任务：起草／改稿／局部生成／结构建议／终稿检查。
- 输出：MVP／完整通稿／局部内容／改稿／终稿。
- 素材：可成稿／可交有明确缺口的工作稿／核心事实需补充。
- 主类型：新品发布／公益与社会责任／活动举办／专家观点／全年回顾，只选一个；按主线分类，不按素材中出现的单个元素分类。
- 对象：to C／to B／to G／混合。to C写用户可感知变化，to B写经营、渠道或产业价值，to G写规则、治理或公共价值。
- 渠道：用户指定优先；未指定时使用主流综合媒体硬新闻风格。

写作任务读取`writing-rules.md`和一个对应类型卡：

- 新品发布：`references/types/new-product.md`
- 公益与社会责任：`references/types/public-interest.md`
- 活动举办：`references/types/event-news.md`
- 专家观点：`references/types/expert-view.md`
- 全年回顾：`references/types/year-review.md`

只有「终稿／正式版／可发布版本／发布前检查／风险检查／终审」才读取`final-review.md`。只有新闻价值不足、事实边界不清、是否值得发或可能放大争议时才读取`references/knowledge-map.md`。不要递归读取其他PR Skill；需要最终取舍时再把最小交接包交给`judgment-hub`。

## 事实底线

- 事实只能来自用户材料或已核验来源。不得补写时间、数据、机制、身份、案例、引语、政策依据、第三方观点或机构背书。
- 不改变事实状态，不把计划、试点、探索或目标写成已完成、全面落地或既成成效。
- 不把平台、样本或个案数据外推为全国、全行业或全社会结论；不得改写统计对象、时间窗口、范围、品类名、产品名或指标口径。
- 先从已有材料核对「谁做了什么」；缺失且无法可靠确定时，只询问核心事实。审阅工作稿可在必要位置使用明确`【待补：事项及影响】`并在稿后汇总；不按缺口数量阻断交付。正式可发布版须解决所有影响发布的缺口。
- 能写事实就不写口号，能写动作就不写价值判断，能写场景就不写抽象概念。
- 标题和小标题使用新闻陈述句，说明主体与动作；只有素材支持时加入数据、机制、范围或结果。禁用纯口号、疑问句和感叹句。

## 起草与追问

内部确认「核心动作是什么」和「外界应形成什么可被事实支持的认知」。材料足够时直接写；只有缺失信息会改变新闻点、事实边界或渠道写法时才追问，最多两个问题。用户要求写稿、起草一版或基于公开信息写稿时，默认交付完整可审阅稿，不增加MVP确认轮次。

## 输出调度

- 写新闻稿、通稿或起草一版时，默认输出完整可审阅稿。
- 只有用户要求先看方向、标题、结构或比较新闻点时输出MVP；已请求的后续正文继续完成。
- 只要求标题、导语、小标题、结尾或某段时，只输出该范围。
- 改稿时锁定用户未要求修改的内容。
- 终稿类请求先完成正文，再执行`final-review.md`；日常写作不展示检查过程。
- 用户对完整稿修改两轮以上且发布意图明确时，直接进入终稿审查；意图不明且审查会显著改变输出时才询问。

## 交付门禁

按顺序检查：本文件事实底线→`writing-rules.md`对应失败条件→当前类型卡失败条件→终稿阶段的`final-review.md`。对事实错误和超出证据的主张先修正；缺口仅影响部分时交付其余可用内容并标明工作稿状态。只有缺失答案会改变核心新闻事实或关键行动时追问。类型结构与篇幅建议不构成硬失败；终稿阶段按真实发布缺口说明风险。
