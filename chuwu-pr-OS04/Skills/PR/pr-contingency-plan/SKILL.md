# 公关预案

> 分享版说明：先读[依赖与使用范围](../../../docs/DEPENDENCIES.md)。本包保留方法与工具，未包含个人知识库、历史案例及运行状态；未附带的知识路径不代表已读取的证据。


> 归属说明：本Skill由初五维护，属于初五的个人Skill体系。分享或再分发时请保留本归属说明及已有来源、作者和许可声明。

## 定位

预案不是追求零风险。零风险通常不存在。

预案要做的是：在动作上线前，把可能消耗信任、引发误解、被对手放大、被媒体截图、被监管追问的点提前拆开，然后判断哪些要改动作，哪些备口径，哪些只监测。

最终产出三样东西：

- 这次最可能被挑什么。
- 被挑时能公开署名怎么答。
- 上线前哪些地方必须改、必须备、只需看。

## 知识调用

默认按本文件完成预案。遇到高风险动作、责任归因、爆料格式、平台传播、利益相关方复杂或组织取舍问题时，读取 `references/knowledge-map.md`。

知识调用后仍要落到三类处理：必须改动作、必须备口径、只需监测。不要用理论解释替代上线前清单。

## 先定标

不要一上来扫风险。先判断这次动作服务什么：

- 曝光。
- 信任。
- 品类教育。
- 风险修复。
- 行业地位。
- 政策合法性。
- 渠道或用户承接。

不同目标能承受的争议不同。短期声量不能透支长期信任。

## 路由

命中高频场景时，按需读取对应reference；其中步骤为模块菜单，按本次动作、素材和决策范围选择，不自动扩展成完整研究项目：

| 场景 | 读取 |
|---|---|
| 品牌出现在综艺、纪录片、直播、联名等内容中 | `references/content-placement.md` |
| 产品上新、升级、换配方、换包装 | `references/product-launch.md` |
| 明星、达人、IP、KOL 合作 | `references/spokesperson-fandom.md` |
| 换厂、换渠道、规则调整、服务政策变化 | `references/change-issue.md` |

如果不属于四类，不要硬套。走通用流程即可。

## 通用流程

```text
定标 → 对象研究 → 历史与同类回查 → 六格风险扫描 → 外部攻击推演 → 口径与处置 → 收口
```

一次动作涉及多类时，只补充新增且相关的模块，共享事实与检查复用，输出收成一份预案。

## 六格风险扫描

六个角度作为内部扫描清单保留，每个角度记录检查状态与依据范围。正文优先呈现重点风险和影响上线判断的缺口，不为填满六格强行制造风险：

- **动作本身**：定价、承诺、姿态、价值立场是否招打。
- **产品或内容交付**：产品、服务、内容、活动是否有失败模式。
- **相关方**：用户、员工、合作方、渠道、特定群体是否会觉得被冒犯或受损。
- **规则环境**：法律、监管、平台规则、行业规范有没有红线。
- **历史旧伤**：品牌、行业、合作对象过去的问题会不会被翻出。
- **关联方与对手**：代言人、供应商、平台、竞品、恶意账号是否会把风险传导过来。

每个维度使用以下状态，不能用一句「暂无风险」合并：

- **已发现风险**：当前材料支持具体失败路径，写明风险与依据；尚未发生的后果仍标为预测。
- **已检查未发现**：已检查相关材料，在本次范围内未发现具体风险；说明检查了什么及范围限制，不代表风险为零。
- **证据不足**：缺少会影响判断的材料，列明缺口、由谁补证以及补证前建议。未检查、拿不到资料或只有单方口头保证，不能转成「已检查未发现」。
- **不适用**：该维度与本次动作无实质关联，简述原因；资料缺失不属于不适用。

每项重点风险需连接**触发条件、具体依据、可能后果与判断边界、建议动作、责任人与责任缺口**。责任人未提供时标「待指定」及所需职责，不虚构姓名或内部承诺。证据缺口同时说明补证结果怎样改变建议；仅在缺口会改变上线安全性或关键承诺时，把补证设为前置条件。

外部攻击与质疑推演是情景假设。说明什么条件下可能出现、依据来自当前材料还是可比案例；不得把想象中的媒体质疑、竞对动作、监管反应或传播量级写成已发生或确定会发生。

## 处理分三类

对已有依据的风险和必要的条件化处置，落到三类之一。证据不足的项目先明确补证动作与决策条件，不用分类掩盖未知：

- **必须改动作**：已确认产品、承诺、合作或利益安排存在实质问题，说明要改什么及依据。区分真实交付缺陷、宣传超过证据和单纯缺少凭证：分别评估修正交付、收窄或撤回主张、补证；不要因材料缺失直接要求改产品。
- **必须备口径**：动作可以做，但外部会追问，需要可公开、可核验、能一致执行的回答。
- **只需监测**：风险存在但不值得主动解释，设监测点和升级红线即可。

口径标准：

- 能公开署名。
- 对得上事实。
- 不扩大承诺。
- 不把计划写成结果。
- 不用情绪安抚替代事实解释。

## 输出组织

以下是内容组织参考，按本次材料与决策需要合并栏目；六维留作内部覆盖检查，正文聚焦关键风险、证据缺口与行动，不逐格凑篇幅。

```text
结论
一句话判断这次动作的舆情底色、最大风险和上线建议。

一、动作目标与舆情底色
写这次动作服务什么，外部会按什么逻辑理解它。

二、风险地图
呈现重点风险与关键检查状态；每项连接触发条件、依据、可能后果、动作及责任缺口。未发现风险注明检查范围，证据不足不得写暂无风险。

三、外部攻击推演
按相关性写媒体、用户、竞品、监管或特定群体可能怎么质疑，明确标为情景假设，并写触发条件与依据。

四、应对口径
一问一答。只写能公开署名、事实兜得住的话。

五、上线前清单
分成必须改动作、必须备口径、只需监测；补证事项写明责任缺口、所需材料和如何影响上线建议。
```

## 质量红线

- 不用「加强沟通」代替口径。
- 不用口径掩盖事实问题。
- 不把所有风险都写成高风险，不把证据不足或未检查写成无风险。
- 不把推演情景、预期效果或尚未落实的责任安排写成事实。
- 不为了全面列一堆无关相关方。
- 不替业务承诺无法确认的结果。
- 不写灰色执行手段。

如果最后需要在上线、延期、换表达、牺牲传播效果、保护信任之间做取舍，转入 `judgment-hub` 拍板。
