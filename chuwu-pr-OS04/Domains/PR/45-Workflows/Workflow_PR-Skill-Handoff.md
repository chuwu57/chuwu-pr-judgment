# PR Skill最小交接协议

## 用途

只在一个PR专项Skill需要把任务交给另一个Skill时使用。目标是保存已经完成的判断，让下游直接处理新增职责，避免重新阅读原材料、知识地图和通用框架。

## 八字段交接包

```markdown
## PR交接包
- 决策主体：
- 时间锚点：
- 已确认事实：
- 证据、反证与缺口：
- 最大不确定性：
- 资产与业务影响：
- 可选动作及代价：
- 需要下游决定或产出的事项：
```

「决策主体」说明当前替谁决策；「时间锚点」说明结论对应哪个日期、时段或事件阶段。两项不得塞进事实或不确定性后在下游重新猜测。

「证据、反证与缺口」必须把三者分开：支持材料写证据，能够削弱当前判断的材料写反证，尚未取得的信息写缺口。没有真正反证时明确写「未取得反证」，不得把未证明某事发生写成已经证明它没有发生。

每项只保留会改变下游结论的信息。原文、完整搜索过程、理论解释和已经排除的支线不进入交接包；必要时附精确文件、段落或来源链接。

## 下游读取规则

下游Skill默认信任交接包中已经标明证据状态的事实与边界，先完成自身新增职责。只有出现以下情况时才重新打开原材料：

- 关键事实缺失，无法完成下游任务。
- 交接包内部矛盾或与用户最新信息冲突。
- 用户明确要求重新核验。
- 下游动作会产生新的高风险公开主张。

知识地图同样按缺口读取。上游已经调用并写入交接包的公共框架，下游不重复加载。

## 结束条件

当前Agent持续负责原任务。交接包是内部中间产物；若用户还要求下游稿件、方案或其他产物，继续完成已授权的新增职责，不停在交接说明。专项Skill已经能给出用户需要的最终结果时直接结束。只有仍存在真实取舍、优先级、暂停条件或组织承诺问题时，才进入`judgment-hub`。
